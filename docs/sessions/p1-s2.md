# P1 S2 — Hybrid retrieval (BM25 + FAISS)

## What was built

- A small Okapi BM25 scorer in `app/bm25.py` (pure Python, no extra package). It uses the same stemmer as the offline embedder, so `fees` and `fee` match.
- `RETRIEVAL_MODE=vector|hybrid` and `HYBRID_VECTOR_WEIGHT` (default `0.5`). The default mode is `vector`, so a normal run still does FAISS only.
- Hybrid mode takes a shortlist from FAISS and a shortlist from BM25, puts both scores on a 0–1 scale, adds them with the weight, and keeps `TOP_K`.
- `scripts/eval.py` accepts `--provider fake|ollama` and `--mode vector|hybrid`.
- The README section "Retrieval: vector vs hybrid" has the offline numbers from a real run, and a placeholder for Ollama. Ollama was not running here, so those cells are not invented.
- Unit tests cover BM25 ranking and the score blend.
- `leetcode/valid-anagram.py` is a 26-count solution with a small `if __name__ == "__main__"` check.

## Why

A vector search can miss a chunk that uses the exact word in the question ("500", "PKR", "security deposit") when the cosine score is just under the threshold. A keyword search can miss a paraphrase. Using both covers more questions. It stays behind a setting because the old threshold was tuned for cosine, and the blend changes that number.

## How it works in simple words

**Vector search** turns the question and each chunk into a list of numbers and asks "which lists point the same way?" Close meaning can match even when the words differ.

**BM25** asks "which chunks contain these words?" A word that shows up in one chunk counts more than a word that shows up in every chunk. Extra repeats help, then level off. A very long chunk is discounted a bit, so one shared word in a short rule beats one shared word buried in a long page.

**Why combine them:** each one fails a different question. The blend used here is a weighted sum, half and half by default:

`0.5 * cosine (clamped to 0–1) + 0.5 * (this chunk's BM25 / the best BM25 in the shortlist)`

Reciprocal rank fusion was the other common choice. Its scores are about `1/60`. `MIN_SCORE` is 0.15 (fake) or 0.45 (Ollama), so fusion would refuse every question. The weighted sum stays between 0 and 1, so the same gate still means "not close enough".

On the offline eval (`MIN_SCORE=0.15`, weight `0.5`) hybrid hit@1 went from 95% (19/20) to 100% (20/20), and page hit@4 from 80% (4/5) to 100% (5/5). Refusal fell from 100% (4/4) to 75% (3/4): "What is the principal's phone number?" matched "Principal" and "phones" in the exam rules, and the blended score was 0.54. Those words are in the file. The phone number is not.

## Five interview questions

1. **What is the difference between BM25 and a vector score?**
   BM25 is a keyword score: shared words, with rare words worth more. A vector score compares meanings. "Tuition paid after the 10th" can match "late fee" by vectors even if the chunk never says "paid".

2. **Why not replace FAISS with BM25?**
   BM25 misses paraphrases, and it fires when the right words are in the wrong rule (the principal's phone number). FAISS is the default because the threshold and the tests were built for it. Hybrid is there when you want both signals.

3. **Why a weighted sum instead of reciprocal rank fusion?**
   Fusion only looks at rank, and the score is tiny, so `MIN_SCORE` would refuse everything. A weighted sum stays on a 0–1 scale the existing gate can still read. The trade-off is that the number is no longer raw cosine, so you retune the threshold.

4. **Why did hybrid refuse less often on the fake provider?**
   The best keyword hit is scaled to 1, then half of that is added. A chunk that merely contains "principal" or "phone" can clear 0.15 even when the cosine was 0.13. That is a real failure on this set, not a better refusal rate I forgot to write down.

5. **What are the time and space costs of `leetcode/valid-anagram.py`?**
   One pass over both strings: time O(n). The count array is always 26 long: space O(1). That assumes the lowercase English letters the problem allows. A different alphabet would need a map, and space would grow with the alphabet, not with the string length.

## How I'd explain this

Vector search matches meaning and BM25 matches the actual words, so hybrid adds those two scores instead of trusting only FAISS.
I kept vector mode as the default, because the refusal threshold was tuned for cosine, and I used a weighted sum so the score stays between 0 and 1.
On the offline eval, hybrid found the academic-year line and the right fee page, and it also answered a phone-number question that is not in the documents, because the exam rules mention the principal and phones.
