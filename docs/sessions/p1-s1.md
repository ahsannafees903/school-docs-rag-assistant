# P1 S1 — Run it fully local on Ollama

## What was built

- Ollama is the default chat and embedding provider: `llama3.2:3b` and `nomic-embed-text`.
- `Settings` and `.env.example` use those defaults. `llama3.1:8b` is the chat model to switch to on a 16 GB RAM machine.
- The offline `fake` provider is unchanged. Pytest and CI still use it, so they do not need a running Ollama.
- `PROVIDER=openai` is deprecated. A normal run does not read or send a paid API key.
- `NOTES.md` walks ingest → chunk → embed → FAISS → retrieve → refusal threshold → LLM → citations.
- The README has a "Runs fully local, no paid API key" setup.
- `leetcode/two-sum.py` is a one-pass hash-map solution with a small `if __name__ == "__main__"` check.

## Why

A demo that needs a paid API key fails on a laptop with no credits and no network. Local Ollama is the path a reviewer can run. The fake provider stays so the test suite does not depend on a model server.

## How it works in simple words

Copy `.env.example` to `.env`. It already says `PROVIDER=ollama`. Pull the two models, ingest the sample school docs, and start the API. A question is embedded, FAISS finds the nearest chunks, a weak score refuses before the model is called, and a strong score goes to Llama 3.2, which answers and cites the file and page. Tests never take that path: `tests/conftest.py` forces `provider="fake"`.

## Five interview questions

1. **Why is the default Ollama, not the fake provider?**
   Fake is deterministic and needs no model, which is what tests want. The default a person runs should be a real local model, with no API key.

2. **Why refuse before calling the LLM?**
   If the nearest chunk is a weak match, the model will still try to answer and may invent a fee or a date. The threshold makes "not in the documents" cheap and testable.

3. **Why two models?**
   `nomic-embed-text` only turns text into vectors so FAISS can search. `llama3.2:3b` writes the sentence. On 16 GB of RAM you can set `OLLAMA_CHAT_MODEL=llama3.1:8b`. Changing the embedding model means rebuilding the index, because the old vectors would not match.

4. **What are the time and space costs of `leetcode/two-sum.py`?**
   One pass and a hash map: time O(n), space O(n). Each number is stored once, and the complement lookup is O(1) on average.

5. **How do tests pass with Ollama switched off?**
   The fixtures build `Settings(_env_file=None, provider="fake")`. The Ollama HTTP client is tested with `httpx.MockTransport`, so those tests never open a socket. CI also runs `PROVIDER=fake python scripts/eval.py`.

## How I'd explain this

I made local Ollama the default so the school-docs assistant runs with two `ollama pull` commands and no paid API key; tests still use the offline fake provider.
A question comes in, FAISS returns the closest chunks, and if the best score is under the threshold we refuse before Llama speaks; otherwise `llama3.2:3b` answers and we attach the file and page.
`llama3.1:8b` is the same chat step on a 16 GB machine, and the embedding model stays `nomic-embed-text`.
