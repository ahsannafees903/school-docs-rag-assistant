## Why

## How it works in simple words

You upload a school PDF. The app pulls the text out page by page and cuts it into pieces of about 400 characters, with 80 characters repeated so a sentence on the cut is still findable. Each piece becomes a list of numbers. Those lists go into a FAISS index; the words, file name, and page stay in SQLite.

Someone asks "what is the late fee?". The question becomes the same kind of list of numbers. FAISS returns the closest pieces. If the best score is too low, the app says it could not find the answer and never asks the language model. If the score is high enough, local Llama writes a short sentence from those pieces only, and the response includes the file, the page, a snippet, and the score.

## Five interview questions

1. **Walk through what happens when a parent asks a question.**
   The question is embedded with the same model that embedded the chunks. FAISS returns the top 4 by cosine similarity (inner product on normalised vectors). Chunks under `MIN_SCORE` are dropped. If nothing remains, the response is the fixed "not in the documents" sentence, `grounded` is false, and the LLM is not called. If something remains, those chunks are numbered and sent to local Llama with a prompt that says to use only that context. The JSON answer includes the sentence plus each source's file, page, snippet, and score. On the offline demo, "What is the late fee if tuition is paid after the 10th?" cites page 2 of `fee_structure_2026-27.pdf` and the score is about 0.54.

2. **How do you stop the model from hallucinating a fee or a date?**
   The first stop is the threshold: a weak nearest chunk never reaches the model, so there is nothing for it to embroider. The second stop is the system prompt, which says to use only the numbered passages and to reply with the refusal sentence when they do not contain the answer. If the model does reply with that sentence, sources are cleared and `grounded` is false. Refusing before the call is the one we test, because it does not depend on the model obeying.

3. **Why chunks of 400 characters with 80 of overlap?**
   A school rule is usually one or two sentences ("late fee is 500 PKR after the 10th"). A short chunk keeps that rule alone, so the citation and the snippet a parent sees point at the rule rather than a whole page. The 80-character overlap is about 20%, so a sentence that sits on a boundary is still inside a chunk on either side. Breaks snap to a paragraph, line, sentence, or word, so words are not cut in half. On the fake embedder, 400/80 was the size that kept every out-of-scope question refused and still hit the right document 95% of the time. Longer policy documents, or a real semantic embedder, may want 800–1200; both numbers are settings.

4. **How do you measure retrieval quality, and what can't this eval tell you?**
   `scripts/eval.py` asks 24 hand-written questions (20 answerable, 4 out of scope) against the four sample documents. A hit counts only when the expected file is among the chunks that also clear `MIN_SCORE`, which is what a user would be shown. The offline fake provider, vector mode, `CHUNK_SIZE=400`, `TOP_K=4`, `MIN_SCORE=0.15` gives hit@1 95% (19/20), page hit@4 80% (4/5), and refusal 100% (4/4). That is a regression check. The embedder is lexical, the set is small and written by the same person who wrote the documents, and the weakest answerable question and the strongest out-of-scope question both scored 0.132, so the margin is one threshold step. It does not say how `nomic-embed-text` behaves, and it does not say hybrid is safer: hybrid found the missed academic-year line and also answered a phone-number question that is not in the files.

5. **Why Ollama instead of a paid API?**
   A portfolio demo that needs a key and credits fails on a laptop with neither, and it would send school text to someone else's server. Ollama keeps chat (`llama3.2:3b`, or `llama3.1:8b` on 16 GB) and embeddings (`nomic-embed-text`) on the machine. The trade-off is local RAM, a model you have to pull, and usually a weaker writer than a large hosted model. Tests do not pay that cost either: they force the fake provider, so CI never starts Ollama and never calls a paid API. `PROVIDER=openai` is deprecated and unused unless you set it yourself.

## How I'd explain this

A parent uploads the fee PDF and asks about the late fee; we embed the question, FAISS finds page 2, and because the score clears the threshold local Llama answers with the file and the page.
If the closest chunk is too weak we stop there and say the documents do not cover it, so the model never invents a number.
Ollama stays on the laptop with no API key, chunks stay short so a citation is one rule, and the eval is a 24-question regression check, not a claim about a hosted model.
